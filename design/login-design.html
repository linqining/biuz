BiuZ 移动端客户端 · 登录与连接 高保真设计稿

本专项稿承接设计规范 v2.4 第 9 章「登录与连接」，设计两条登录路径：路径 A · 账号 OAuth（O1–O3）——「使用 Z.ai 账号登录」为主按钮，点击后在应用内授权 Sheet（内嵌浏览器视图：顶部关闭按钮 + 加载进度条 + 授权页内容；页内为远端授权页示意，外观跟随系统）打开 chat.z.ai/api/oauth/authorize，不跳系统浏览器；redirect 导航在视图内被拦截（code + state，state 必填缺失即报错），POST /api/v1/oauth/token 交换 tokenSet{accessToken, zcodeJwtToken, expiresAt} 与 userInfo{displayName, avatarUrl}，凭据仅存 Keychain，后续请求 Authorization: Bearer；BigModel 智能体平台登录为高级选项（{origin}/login?appId=zcode）。路径 B · 桌面配对（L1–L5）——「连接桌面端」为次入口：iOS 连接对端是桌面机上运行的 zcode-server 进程（zcode --web --host 0.0.0.0，默认端口 3030，非 loopback 自动生成访问令牌），而非桌面 Electron App 本身。凭据传递 = 扫描连接二维码 / 通用剪贴板一键填充 / 手动输入 host:port + token；随后 GET /api/server-info 发现与鉴权 → WS /ws?token=…（web-remote-replayable）→ v4 握手（clientKind=mobileApp）→ 以 workspaces[0] 载入工作区。服务器令牌即「服务器密码」：仅存 Keychain、无过期撤销，401 即引导重扫。全部令牌、组件与基准稿（zcode-mobile-design.html 屏 01–14）完全一致，只增不改。

双路径信息组织
  • 路径 A（主按钮）：「使用 Z.ai 账号登录」= OAuth 账户层（云端分享 / Coding Plan 额度），对应 web 端 zaiWebOAuthProvider；ZAI 为默认 Provider。

OAuth 机制（接口调研转引）
  • 授权入口（ZAI，默认）：{origin}/api/oauth/authorize?redirect_uri=…&response_type=code&client_id=…&state=…，origin 缺省 chat.z.ai（webZaiOAuthConfig.ts:26-29、54-56；源码注释：ZAI 走 /api/oauth 前缀，/auth/oauth 是旧入口）。
  • 授权入口（BigModel，高级选项）：{origin}/login?redirect=…&appId=…&state=…，appId 缺省 "zcode"（webZaiOAuthConfig.ts:39-47、59-61，buildAuthorizeUrl 分支）。
  • state：一次性随机值，发起时生成并本地暂存；回调时必填校验，缺失即报错（parseCallbackParams）——防 CSRF。
  • 绑定假设（gaps）：①移动端 redirect_uri 需自定义回调 scheme（如 zcode://oauth/callback），web 端用 webShareCallbackUrl（webZaiOAuthConfig.ts:62），移动端注册名为绑定假设；②client_id 来自部署环境变量 VITE_ZAI_OAUTH_CLIENT_ID，移动端缺省值与可配置性为绑定假设。
触控与安全区

  • 顶部 54px（灵动岛）/ 底部 34px；协议脚注距底 --safe-bot + 12px，协议链接 padding 外扩 44px 热区。

应用内授权 Sheet（O2-A · 用户已决策）
  • 应用内完成，不跳系统浏览器：点击 O1 主按钮 → 授权 Sheet spring 升起（2.7：背景压暗 + 缩放 0.96）；授权页由 chat.z.ai（或 BigModel）在内嵌浏览器视图中渲染。
  • 稿内页内区域是「远端页面示意」：授权同意页由授权服务器渲染，App 只在回调拿到 code/state——.wv-page 内的站点标识、scope 行、授权/取消按钮均为该远端页面的信息层级示意（帧内虚线胶囊已标注），不是 App 自绘 UI；E2E 与视觉验收只针对 Sheet 容器与 .wv-bar/.wv-progress，不得按稿断言授权页内部外观。
  • 载体与注入边界：建议 ASWebAuthenticationSession 优先——关闭按钮/进度/取消等 chrome 由系统提供，页面即 chat.z.ai 真实网页，与 Safari 共享会话 Cookie；无外观控制 API，禁止注入自绘同意页（伪造授权页=钓鱼反模式）。WKWebView 备选：仅做容器 + redirect 拦截，同样禁止注入或改写授权页内容。
  • 外观跟随系统（非 App 设置）：授权页深浅由授权服务器页面与系统决定——屏 12 用户强制 Zai Dark/Light 时此页不随应用设置，以真机实测为准；App 内可保证的只有 Sheet 容器底色与状态栏（顶部 --safe-top 区域）。
  • 关闭手势：✕ 点击（视觉 40×40、命中区外扩 ≥44）/ Sheet 下拉抓手关闭（本 Sheet 允许下拉关闭，不同于审批 Sheet 3.3 裁定）/ 页内「取消」——三者等价，均按用户取消处理（O3-B 中性结果，非故障；ASWebAuthenticationSession 载体下页内「取消」即系统 chrome 的 Cancel）。

回调拦截与授权中（O2-B 四步）
  • 回调拦截：「授权并继续」后授权服务器 302 到 zcode://oauth/callback，redirect 导航在内嵌视图内被拦截（不真正加载、不离开 App）；解析 code（或 authCode，双兼容，parseCallbackParams）与 error；出现 error 参数 → 直接转 O3-B 失败态。
  • 校验 state：与发起时本地暂存值严格一致；state 必填，缺失即报错——不匹配/缺失转 O3-B（防 CSRF，不接受静默降级）。
  • 交换令牌：POST /api/v1/oauth/token，JSON body {provider, code, redirect_uri, state}；响应 {code:0, msg, data:{token(zcode JWT), zai:{access_token}, bigmodel:{access_token}, expires_in, user}}（exchangeToken/normalizeTokenResponse，tokenUrl 见 webZaiOAuthConfig.ts:56）。
  • 凭据落地：tokenSet{accessToken, zcodeJwtToken, expiresAt} + userInfo 入 Keychain（web 端对应 localStorage/sessionStorage，browserOAuthCredentialRepo.ts:40-76，转引）。
  • 无回调兜底：授权页长时间无进展（加载失败/卡住）超过 60s 出现「授权页未响应？」引导条（o2-card-nocallback）+ 44px「关闭并重新发起」（o2-act-restart，重置一次性 state 再走一遍 O1→O2-A）；用户主动 ✕/取消属有意退出，直接转 O3-B，不出 60s 引导；「取消登录」始终可用。
  • 日志掩码：code/token/jwt 一律 ***，不回显完整凭据。
进度与触控
  • 四步进度与 L2 同构（.step-row）：完成=绿勾+耗时、进行中=蓝 spinner、未到=灰虚圈；计数含进行中（2 完成 + 1 进行中 = 3/4、条宽 75%）。
  • 遵循 5.9 加载口径：分步清单 + 单点 spinner，无骨架屏；「取消登录」48px（热区 ≥44），立即中断交换并清除暂存 state。
  • 顶部 54 / 底部 --safe-bot；授权 Sheet 内动作「授权并继续」48px、「取消」44px；✕/刷新热区 40×40（视觉）含外扩 ≥44 命中区；成功收尾 → O3-A（crossfade 250ms）。

成功态（O3-A）
  • userInfo 直出：displayName（主标题）+ username / id（次级）+ avatarUrl 头像位（toUserInfo 兼容 user.id/user_id、name/email、avatar/avatarUrl 与 data:image base64——无图时渐变+首字母兜底，同基准稿头像做法）。
  • tokenSet 摘要：accessToken（Provider access_token，掩码）、zcodeJwtToken（data.token，zcode JWT）、expiresAt（由 expires_in 换算）——全部仅存 Keychain。
  • Provider 徽章：ZAI 用 .pill done（绿·渠道来源语义），Coding Plan 用 .pill tag（紫·能力标签语义）。
  • 「开始使用」→ L1 连接页（未配对）或任务看板（已配对，crossfade 250ms）。
失败 / 取消态（O3-B）
  • 遵循 5.9 失败态统一模式：错误卡（图标 + 一句结论 + mono error=…）+ 唯一主 CTA（重新登录） + 次级动作；用户取消为中性结果非故障——文案不指责、状态可恢复。
  • 失败分支五态：①用户取消（Sheet ✕ / 下拉 / 页内取消，无 code 亦无 error）②error 参数（授权服务器拒绝）③state 缺失/不匹配（必填缺失即报错）④交换失败（超时 / code≠0）⑤Keychain 写入失败（交换成功但凭据落地失败）。
  • 次级路径不死路：「改用 BigModel 登录」（换 Provider 重发起，{origin}/login?appId=zcode）与「跳过 · 连接桌面端」（转 L1，登录非使用前提）均 44px。
  • 重试时重置一次性 state，保留 client_id / redirect_uri 等静态发起参数；错误回显不含 code/token 明文。
触控与安全区
  • 主按钮 48px；换 Provider / 跳过 44px；错误对照行信息型不可点。
  • 顶部 54 / 底部 --safe-bot；O3-A 凭据摘要行高 ≥44px（信息型）。
