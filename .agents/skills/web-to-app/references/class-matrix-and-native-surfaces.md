# 类矩阵、原生壳层与真实度量

> 三类「修一处炸一片」的共同根因：**分类粒度不够、原生壳层不在清单、文本用码点而非真实度量**。
> 本文件把这三件事变成可执行的检查动作。

## 0 一句话规则

**改条件 / 样式 / 门控 / inset 之前，先写出这个类有哪些成员；修完之后逐个成员点名验证。**

「所有含 X 的页面」「所有用 Y 组件的界面」几乎从不是同一个类——它们通常按行为分成两类甚至
三类，而你只会验证你想到的那一类。

## 1 类矩阵（class matrix）

改动前先写：

```
class = {全部成员} × platform × state
```

| 维度 | 要回答的问题 |
|---|---|
| 成员 | 这个类**到底包含哪些页面/元素**？逐个列出（不是「等等」） |
| 边界 | 哪些**看起来像**但不属于这个类？为什么？ |
| 平台 | 同一个成员在各端是否有不同实现路径（原生组件 / 自绘 / WebView）？ |
| 状态 | 每个成员有哪些状态（默认/加载/空/失败/离线/禁用/展开/选中）？ |

**修复后的验证表**（每个成员一行，四选一，禁止留空）：

| 成员 | 验证方式 | 结论 |
|---|---|---|
| A 页面 | test / evidence / seam / blocked | 受影响的写证据；不受影响的写**为什么不受影响** |

反例：把「自管 inset 的页面」与「壳层给 inset 的页面」合并成一类，修好前者让后者顶进状态栏。
正例：分类判定收敛到**单点函数**（一个 key→bool 的映射），并为每个成员写一行字面量断言
（含反例成员），这样下次新增成员会被测试逼着做决策。

## 2 原生壳层是页面的一部分

系统画的东西不是「不用管」，它同样在用户视野里，同样会错：

| 壳层 | 必须进契约的点 |
|---|---|
| 启动屏 / splash | 构图与 web 加载页同源（图标、字标、间距）；**图标必须落在圆形安全区内**；背景色与首屏一致（防启动闪色）；层序（先图标后字标，还是相反） |
| 状态栏 / 导航栏 | 内容延伸（edge-to-edge）时，**系统栏图标明暗必须跟应用主题**，不是跟系统深浅——否则「系统深色 + 应用浅色」会出现白图标压白底 |
| insets（刘海/手势条/导航条） | 每个全出血页面**只能有一个 owner**：要么页面自管，要么壳层统一给，禁止两处都加（会双倍留白） |
| IME / 软键盘 | 键盘升起时安全区内元素是否被顶出可点区域；主操作是否常驻键盘上方 |
| 转场 | 冷启拦截、登录成功、返回栈的动画是否与 web 的方向/时长同构 |

## 3 文本：字素簇 + 真实字体度量

按「字符数」估算宽度、手调宽度表、按码点截断——这三件事在中英混排、emoji、组合字形、
窄体字上全部会错。

- **宽度**：用平台真实文本测量（`TextMeasurer` / `CanvasTextMetrics` / `NSAttributedString.size()`），
  不用码点数乘平均值。
- **截断**：按**字素簇**（grapheme cluster）二分，不按码点切；**省略号计入宽度预算**。
- **预算来源**：从 web 的 `maxWidth` 与容器尺寸**同比例**派生，不手抄像素值。
- **行高/字号**：跟随两端排版栈换算（见 `ui-parity.md` 适配栈判定），不用固定 `px`。

判定：给一个「必然溢出」的样本（超长昵称 / 长文件名 / 长 URL+CJK），三端都不得冲出容器。

## 4 动作按目的地映射，不按 API 名

`goBack()` / `pop()` / `dismiss()` / `navigate(-1)` 在语义上并不等价。判断依据是 web 的
**目的地**，不是函数名：

| web 写法 | 语义 | 端上正确的映射 |
|---|---|---|
| `navigate(-1)` / `history.back()` | 回上一页 | pop |
| `navigate('/home')` / `navigate(Home)` | **回首页（可能清栈）** | 回根 / 清栈后跳根，**不是** pop |
| `router.replace(...)` | 替换当前页（不可回退到被替换页） | 替换而非 push |
| `dismissDialog()` | 只关弹层，页面不动 | 关 sheet |

反例：把「回首页」实现成「返回上一页」，用户从二级页进来就会停在别处。

## 5 共享组件跨宿主不变量

一个组件被 ≥2 个宿主使用，就必须有**跨宿主的行为不变量**与断言：

- 几何不变量：最小高度、内边距、图标尺寸不随宿主变化。
- 文本不变量：同一 maxLines / 截断策略 / 字号阶梯。
- 层序不变量：浮层永远在内容之上；同一 zIndex 策略。
- 交互不变量：同一动作在三处触发的行为一致（尤其「关闭」类动作）。

做法：为共享组件写一份「宿主清单 + 不变量断言」，任一宿主改样式时按清单回归。
