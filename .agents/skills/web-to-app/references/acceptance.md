# 多端验收对比（acceptance）

> 场景：用户说"验收 XX 页 / 对比 XX 多端一致性"。产出：web 基线 + 各端实拍的
> 逐屏并排比对结论，差异逐条裁决（缺陷入 BACKLOG、刻意不同入差异台账）。

## 流程总览

```
① web 基线采证（capture.py，统一仿真规格）
② 各端实拍（测试缝直达 + 真实入口，模拟器/真机）
③ 逐屏并排比对（模型读图 + DOM/量取数据佐证）
④ 裁决留痕（BACKLOG / 差异台账）+ 差异标记对账
```

## ① web 基线

```bash
python3 <skill>/scripts/capture.py status       # 先确认登录态符合该页要求
python3 <skill>/scripts/capture.py shot <key> --scrolls N --dom
```

- 验收必须用**与 App 同账号态**的截图（游客态 App 配游客态 web）。
- 截图前必须过稳定门（`capture-pipeline.md` §3）；meta 里 `UNVERIFIED`/`unstable`
  的采集不得作基线。
- web 侧有变更时按 `sync-workflow.md` §A 重采，不要拿过期基线裁决。

## ② 各端实拍

原则（各平台具体命令按项目工程写死在验收脚本里，产物约定统一）：

- **测试缝直达**：每页一个直达入口（iOS 启动参数 / Android 深链 extra /
  微信小程序页面路径 + automator / 其他平台等价），不依赖 UI 点击注入 —— 快且稳定
- 产物目录：各端 `artifacts/acceptance-run/<NNN>-<name>.png`，**与 web 采证同名
  （同 key）**，保证逐屏可比
- 长尾页（重内容/实时流）允许加长 settle；多实例并发实拍要加锁防抢设备
- 微信小程序实拍：开发者工具 + `miniprogram-automator`
  （`mp.reLaunch('pages/xx/xx?a=1')` → settle → `mp.screenshot({path})`）；
  真机用预览/体验版 + vConsole。**实拍必须标注版本（开发版/体验版/正式版）**——
  三者域名校验与行为不同，跨版本截图不可比（见 `platform-differences.md` §5）
- 模拟器环境坑：休眠拍黑帧（保活设置）、DNS 代理类绕过采完必须清理、
  模拟器截帧慢的快动画判不了（换真机或录屏）；小程序侧另有「不校验合法域名」
  只在工具生效——工具绿真机挂是环境差异，不是产品缺陷

## ③.5 测试缝边界（防假绿）—— 最重要的一节

启动参数/深链 extra 是为了稳定复现，**不等于真实用户路径**：

- `acceptance_route` 可能把页面钉在 demo/占位态，页面"通过"≠ 真实数据/真实导航链
  已实现
- 每个交互链至少补一次**从真实入口**（首页/列表点击/真实深链）进入的端到端验证
- 证据里分别标 `seam`（测试缝）与 `real`（真实路径）；只交 seam 帧不得判该链通过
- seam 分支必须零用户影响（仅启动参数/extra 生效），不得改生产默认行为

## ③ 逐屏并排比对

对每个 key：Read 各端截图（web 采证 + 各端实拍），按固定清单核对：

1. **结构**：区域/元素齐全（缺块 = P1）
2. **布局**：间距/对齐/层级（明显错位 = P1~P2；可量测的按 `ui-parity.md` 网格法）
3. **素材**：图片/icon 同源、无近似替换（素材错 = P2）
4. **文案**：逐字一致（含 i18n；权威语言包为准）
5. **状态**：空态/加载态/徽章门控条件与 web 采证一致
6. **字体渲染**：无 fallback 字体、无缺字

canvas/WebGL 页没有 DOM 佐证，以截图帧互证 + 网络记录（素材 URL 同源）为主。

## ④ 裁决与留痕

- 每个差异先排除账号态/AB 实验/环境因素（旧构建、基线过期、区域拦截）再定性，
  多帧互证；判不了先入 BACKLOG 待裁决，不留模糊态
- 缺陷 → `docs/PARITY_BACKLOG.md`：`[P1|P2|P3] #编号 页面 — 不一致 ｜ 证据 ｜ 状态`
- 刻意不同 → 差异标记（`diff-language.md`）
- 验收轮末尾跑差异标记对账（前缀取 `diff_language.prefix`，默认 APP-DIFF）：
  `grep -rn "APP-DIFF" <各端源码目录>` 与台账互查（代码↔台账双向存在）
- 验收报告（用户要汇总时）：逐屏表格 `key ｜ web ｜ 各端 ｜ 结论（一致/Pn缺陷/Dn差异）`，
  截图相对路径附上

## 优先级口径

P1 = 结构缺失/错误布局（用户可见硬伤）；P2 = 元素缺失/样式偏差；P3 = 文案/角落细节。
金额类与交互阻断类缺陷一律最高优。

## 全项目验收（波次制）

冷启动收尾或大版本后跑全项目验收：

1. 按页面索引全量列屏（入口页 W1 → 高频 W2 → 次级 W3 → 长尾 W4）
2. 每屏：default 态多端对比 → 交互态矩阵（`interaction-and-motion.md` §1）
   → 动画验收（有动效的页）
3. 多机型矩阵：小屏/标准/大屏 + `fontScale 1.3` + 横屏 + 微信字体变大（见任务包 acceptance.json）
4. 测试用例优先：有真实用户路径用例的页，按用例走 real 路径验证
5. 环境纪律：账号态固定、构建版本固定（小程序含开发版/体验版/正式版）、
  web 基线当日新鲜；环境绕过项（DNS 代理、域名校验关闭等）
  单独登记环境编号，不混入产品缺陷
