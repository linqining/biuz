# 假缺陷排查（false-positive-triage）

> 采证污染制造的幻影缺陷比漏测更贵：返修会去「修」不存在的问题，真缺陷被顺延，
> 而且下一轮会以「已修」的名义掩盖它。**打回单到手，先过这张表再定性。**

## 0 四型污染指纹

| 型 | 指纹（怎么认出来） | 处置 |
|---|---|---|
| **身份态漂移** | 截图内容是登录后界面，但 `meta`/实拍环境是未登录（guest）；或同一批实拍前半登录、后半游客 | 重拍并核对登录态字段；**不修代码** |
| **旧构建 / 冻结产物** | 实拍时间早于修复提交；`versionName`/构建时间/产物 md5 与记录不符；或装的是上一个安装包 | 重装最新构建后重拍 |
| **同帧复用** | 多个不同 key 的截图字节级相同或明显同页；`meta` 里的 URL/路由与 key 不符 | 重拍各自 key，核对页面身份（URL/title/内容锚点） |
| **基线过期** | web 已改版，旧基线仍含已删除区块；实现「缺区块」被当成缺陷 | 重采 web 基线，diff 新旧基线后再裁决 |

补充两型（同源，一并检查）：

| 型 | 指纹 | 处置 |
|---|---|---|
| **状态未触发** | 页面能到，但截图是默认态；采证只证明「页面能到」，未证明「该状态出现」 | 用该状态**专有**的触发（深链参数 / 启动参数 / 状态位），见 `interaction-and-motion.md` 触发优先级 |
| **环境差异** | 设备型号/系统版本/字体/缩放/深浅主题与基线不一致，导致布局与配色看起来「错了」 | 对齐环境后重拍；只在报告里注明差异，不当代码缺陷 |

## 1 排查顺序（60 秒）

1. **证据字段齐不齐**：触发命令、等待条件、设备与视口、登录态、构建标识、截图路径。
   缺字段的打回单**先退回补证**，不进入修复。
2. **比身份态**：基线 `meta` 与实拍时的账号态是否一致，不一致整条作废。
3. **比构建**：实拍是否在修复 commit **之后**构建（旧构建只能证明历史缺陷）。
4. **比页面身份**：截图内路由/标题/内容特征 vs 打回单 key。
5. **比基线时效**：web 基线采集日期 vs 源仓最近改动（`sync_state.py status` 的基线 commit）。
6. 以上都通过，才按真缺陷进入归因（`source-to-contract.md` M1–M17）。

## 2 反假绿：别让「通过」也骗人

假缺陷之外还有反向污染——**假绿**：

- **测试缝把真实启动掩盖了**：用 `--acceptance-*` / fixture 旗标进场的用例全绿，但真实冷启
  路径根本不经过那段代码。验收后必须做一次**不带任何验收旗标的 cold boot**，断言无 fixture
  文案/测试按钮/残留状态（见 `acceptance.md` §seam vs real）。
- **旧二进制**：构建失败被管道吞掉（`xcodebuild … | tail` 退出码恒 0），后续
  `test-without-building` 拿旧产物跑出「全绿」。**判定必须显式**：`echo exit=$?` +
  `grep -c "error:"` + 匹配构建成功字面量；并核对产物 mtime 晚于最新源码修改。
- **构建缓存回放**：某些环境（构建串行化垫片、CI 缓存）会在「判定源码未变」时**直接回放
  上次成功日志并返回 0**，而源码实际已变。日志出现「复用上次构建 / cache hit」类字样时，
  必须强制真实构建再判定。
- **替身服务端不校验载荷形状**：本地全绿 ≠ 真机可用。写在协议层的形状必须另有取证
  （源码/真机回执），替身只证明「客户端逻辑自洽」。

## 3 结论怎么写

每条裁决必须落到三选一，并给出证据指针：

| 结论 | 允许的写法 | 禁止的写法 |
|---|---|---|
| 真缺陷 | `defect` + 机制编号（M1–M17）+ 证据路径 + 类矩阵成员 | 「看起来不对」 |
| 采证污染 | `false-positive:<污染型>` + 重拍证据 | 「无法复现」而不说为什么 |
| 未验证 | `unverified` + 缺什么字段/缺什么触发 | 沉默，或写成 `pass` |

**「没测」必须显式声明**：交付说明里写「未验证 + 原因」，禁止默认沉默当作已测。
